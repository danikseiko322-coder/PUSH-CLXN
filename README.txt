ВАЖНО ПРО АВТОПРОВЕРКУ
Статический HTML сам по себе не может безопасно хранить секретный OAuth-токен.
В этом архиве уже есть backend. Он обращается к DonationAlerts API с серверной стороны и ищет донат по двум условиям:
1. точная сумма тарифа в RUB;
2. уникальный код заказа в сообщении доната.

DonationAlerts указывает, что API требует OAuth-авторизацию, а для списка донатов нужен scope oauth-donation-index:
https://www.donationalerts.com/apidoc

ЗАПУСК
1. Установи Node.js 18+.
2. В папке сайта выполни:
   npm install
3. Скопируй .env.example в .env.
4. Получи OAuth access token DonationAlerts с правом oauth-donation-index и вставь его в DA_ACCESS_TOKEN.
5. Запусти:
   npm start
6. Открой:
   http://localhost:3000

ДЛЯ ПУБЛИКАЦИИ
Нужен хостинг, который запускает Node.js (например VPS/Render/Railway и т.п.).
На обычном статическом GitHub Pages автоматическая проверка DonationAlerts этим способом работать не будет.

БЕЗОПАСНОСТЬ
Не вставляй DA_ACCESS_TOKEN в index.html и не отправляй его клиентам.
Для настоящего магазина также стоит добавить базу данных, админ-модерацию, HTTPS и защиту от повторного использования одного платежа.

ИСПРАВЛЕНИЕ АВТОПРОВЕРКИ
В новой версии сообщение «Сервер проверки пока не настроен» больше не маскирует все ошибки подряд:
- если backend не настроен — показывается отдельное сообщение;
- если OAuth-токен неверный/нет права oauth-donation-index — показывается отдельная ошибка;
- если DonationAlerts API временно недоступен — показывается отдельная ошибка;
- проверка учитывает пагинацию DonationAlerts и не позволяет использовать один donation ID для двух заказов.

Для работы всё равно нужен сервер Node.js и действующий OAuth access token DonationAlerts.
Пароль от аккаунта DonationAlerts для API не нужен и не должен находиться в коде сайта.
