PUSH CLXN — LIVE STRIPE SETUP

1. Open Stripe Dashboard -> Developers -> API keys.
2. For a production website, use a live secret key (sk_live_...) or a restricted live key (rk_live_...) with the required Checkout/payment permissions. A restricted rk_live key only works if its permissions include creating/reading Checkout Sessions and the required payment resources.
3. Put the key only in the local .env file:
   STRIPE_SECRET_KEY=...
4. Put your live publishable key in:
   STRIPE_PUBLISHABLE_KEY=pk_live_...
5. Keep .env private. Never upload it to GitHub or paste the secret key into index.html/payment.html.
6. Make sure your Stripe account has a bank account connected for payouts and that payments are enabled.
7. Start with START_FINAL.bat or START.bat.

IMPORTANT
The restricted key previously shared in chat should be rotated/revoked if it has been exposed elsewhere. Do not publish secret/restricted keys.


GLOBAL PAYMENTS & FRAUD PROTECTION

- The Checkout session uses Stripe automatic payment methods, so Stripe can show eligible cards/wallets/payment methods for the buyer's country. This does NOT mean every country is supported: Stripe, card networks, sanctions, local regulations, and your account's capabilities can restrict availability.
- Billing address and phone collection are enabled to improve payment verification and fraud screening.
- 3D Secure is left to Stripe's automatic decisioning/SCA flow.
- Use Stripe Radar in the Dashboard for additional fraud rules/reviews. Do not promise customers that chargebacks are impossible.
- The server verifies the Checkout Session's payment_status before accepting an order and blocks reuse of an already-fulfilled paid order.
- Keep the webhook configured in production and set STRIPE_WEBHOOK_SECRET. The polling check is a fallback; webhook confirmation is the preferred fulfillment signal.
- For the strongest setup, enable Radar and review high-risk payments before delivering valuable digital goods.
